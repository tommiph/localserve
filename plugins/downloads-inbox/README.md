# Downloads inbox

Receive phone files in the PC's Downloads folder and hand magnet links or torrent files to the installed qBittorrent 5 client. The phone uploads over the trusted LAN; torrent contents are downloaded by the PC, not the phone.

Enable this plugin in Settings. Leave **Downloads folder** blank to use the Windows account's Downloads known folder, including its configured redirection. An absolute destination can be selected instead. The default file limit is 512 MiB, configurable up to 4 GiB. Enable **Download torrent contents with qBittorrent** to accept torrents. The standard Windows installation is detected; an explicit qBittorrent executable can be configured. **Torrent content location** offers **Use the Downloads inbox folder** (the existing default) or **Let qBittorrent choose**. The latter leaves the content save path and Add Torrent dialog preference to qBittorrent. Ordinary uploads and received `.torrent` metadata still go to the Downloads inbox folder. No phone app update is required.

In **Transfers**, choose **Get Android app**. Install Sormus Downloads, then choose **Pair a phone** in the PC administrator. Enter the PC's numeric LAN address, a phone name and the eight-digit code in the app. Codes expire after five minutes, are single use and stop accepting guesses after five failures. Phones have independently revocable grants. Pairing grants no administrator access, PC file browsing or access to other phones' receipts. The administrator's existing optional sign-in setting is independent.

Use **Share → Sormus Downloads** or open a supported file/link to send automatically to the paired PC, without opening the Downloads workspace. Launching the app normally retains its file picker and **Send to PC** button. An unpaired receiver opens setup and sends its pending selection after successful pairing. Progress/cancellation appears in the foreground notification; queued shares are processed serially without automatic restart/redelivery. Magnet links can open the app through Android's chooser. Downloaded `.torrent` files with the BitTorrent MIME type can also open it. Ordinary HTTP/HTTPS torrent clicks may stay in the browser, especially on Android 12 and newer: use Share or open the downloaded torrent file. Sormus cannot force another browser to show a chooser. See [Android link routing](https://developer.android.com/training/app-links/create-deeplinks).

The browser Transfers tab also accepts local files and torrent links. Upload progress appears during sending. Files are streamed to an incoming file and published without replacing an existing filename; duplicates gain a numbered suffix. The destination must support hard links, as Windows NTFS does. No received file is opened or executed. For long files, keep the connection available; uploads have a five-minute deadline and a 30-second idle limit. Interrupted transfers do not resume automatically. A service notification keeps an Android upload active while the app is in the background, subject to the phone's battery and operating-system limits.

Explicit torrent uploads are bounded to 4 MiB and validated before handoff. Torrent metadata paths cannot escape the download folder or introduce symlinks. A public HTTP/HTTPS link is fetched with bounded redirects, DNS validation/pinning, time and byte limits. Browser cookies and credentials are not forwarded; share the torrent file itself if its URL requires a website login. Magnet submissions do not fetch metadata in Sormus. qBittorrent's first-run screens must already be completed on the PC. In Downloads-folder mode, per-submission `--save-path`, `--add-stopped=false` and `--skip-dialog=true` arguments use the selected destination. In qBittorrent mode, only `--add-stopped=false` is supplied: neither the location nor the Add Torrent dialog preference is overridden. Neither mode changes qBittorrent's global settings; see [qBittorrent options](https://github.com/qbittorrent/qBittorrent/blob/master/doc/en/qbittorrent.1.md).

**Sent to qBittorrent** means the request was handed to the local client, not that the torrent finished. See qBittorrent on the PC for progress, errors, completion and torrent cancellation. Cancelling a Sormus upload or metadata fetch does not remove a torrent already handed off. Restart never replays a transfer or a potentially delivered torrent. Check recent transfers and the PC before submitting again after an uncertain connection loss.

At most eight transfers may be admitted at once. Receipts retain the latest 256 submissions, with 60 shown per view; idempotency applies within that retained history. URLs are not stored in receipts. Pairing token hashes are private in `data/downloads-devices.json`; client tokens stay in Android's private, backup-disabled app storage. Transfers, grants, downloaded bytes and temporary files are excluded from configuration backups and public source. Restore retains the local grants but disables restored integrations. Interrupted incoming `.part` files may remain after an unclean process exit; they are never published or replayed.

This receiver uses the existing local HTTP server on a trusted LAN. It adds no Internet listener, cloud service or automatic forwarding. Counters and the last received filename are available as explicitly selectable Card fields and four themed ready-made designs. Existing Vistas are not edited automatically.
